# Технология микрофронтенда
В качестве фреймворка для декомпозиции frontend приложения на микрофронтенды (для независимой разработки разными командами) выбран инструмент Module Federation. Что позволяет не раздувать размер бандлов, используя общие зависимости между разными микрофронтендами (так как весь код frontned приложения написан на единой технологии). Единую технологию планируется использовать и в будущем, для возможности быстрого переключения членов любой команды на работу в любом микрофронтенде.

# Перечень микрофронтендов
Проект frontned был разделен на 4 приложения, находящиеся в папке ./frontend/microfrontned
- host - основное приложение: связывает другие приложения, содержит логику переходов между страницами, шапку и подвал
- auth - приложение для аутентификации. Выделение этой сквозной функциональности в отдельный микрофронтенд позволяет
  - отделить аутентификацию от бизнес логики других приложений
  - устранить необходимость изменения других приложений при изменении логики аутентификации
  - проще контролировать связанность частей аутентификации (вход, выход, регистрация)
  - снижает риск возникновеня уязвимостей
- places - приложение с географическими местами. Выделение этой функциональности в отдельный микрофронтенд позволяет
  - независимо развивать функциональность мест
- profile - приложение профиля. Выделение этой функциональности в отдельный микрофронтенд позволяет
  - независимо развивать функциональность профиля

# Запуск
Микрофронтеды запускаются и работают совместно, есть проблемы с загрузкой изображений

Для запуска необходимо выполнить команду
```
docker compose -f ./frontend/microfrontend/compose.yaml up
```
